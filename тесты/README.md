# Проверки

Одна команда из папки с системой:

```bash
npm test
```

Она создаёт **отдельную** базу с демонстрационными данными (ваша рабочая база
не трогается), поднимает сервер на свободном порту, прогоняет все наборы
и печатает сводку.

Всё временное — снимки экрана, тестовые базы, папки обмена — складывается
в `тесты/.вывод` и в git не попадает.

## Зачем это здесь

Система считает деньги магазина. Почти всё в ней доказано не рассуждением,
а проверкой: продажа, возврат, обмен, долги перед поставщиками, комплекты,
права продавца, защита входа, обмен с 1С. Пока проверок нет рядом с кодом,
любая правка — и уж тем более переезд на другой хостинг — делается вслепую:
ошибки в деньгах не падают с сообщением, они молча дают неверную цифру.

## Что проверяется

| Набор | О чём |
|---|---|
| `smoke` | вход, каталог, продажа, права — самое основное |
| `jewelry-test` | металлы, вставки, пробы, вес, бирки |
| `consistency-test` | **сходимость денег**: касса, долги, отчёты, возвраты |
| `diamond-test`, `diamond-ui` | сертификаты GIA/IGI |
| `exchange-test`, `exchange-ui-test` | обмен изделия |
| `import-test`, `sync-full-test` | обмен с 1С: выгрузка, прайс, папка автообмена |
| `locale-test` | валюта, даты, числа |
| `скрипты-test` | **установка и обновление сервера**: bash их понимает, откат на месте |
| `касса-test` | **сверка кассы**: карта в ящик не попадает, возврат уходит, недостача видна |
| `касса-сходимость-test` | **ящик сходится на всех операциях**: обмен, карта, заказы, поставщики, долги |
| `расходы-test` | **аренда и зарплата**: напоминание в срок, зарплата Анны не закрывается зарплатой Марата |
| `скидки-test`, `скидки-ui` | **потолок скидки**: продавец не отдаст изделие за ноль, обходные пути закрыты |
| `приёмка-test`, `приёмка-ui` | **приёмка от поставщика**: долг появляется сам и ровно на сумму; новый клиент прямо в кассе |
| `roles-test`, `roles-ui` | **продавец не видит закупочную цену** |
| `основатель-test`, `основатель-ui` | **три роли**: бухгалтеру открыто всё, кроме панели основателя, журнала и учётной записи основателя; старая база переезжает на три роли |
| `devices-test` | ноутбук и телефоны видят одни данные; нельзя продать дважды |
| `память-test` | **данные переживают выключение**: kill -9 посреди работы, десять раз подряд |
| `тревоги-test` | владелец узнаёт, что копии перестали делаться, а продавец — нет |
| `живое-test` | экран обновляется сам; форма при этом не стирается |
| `audit-test`, `audit-ui` | журнал действий сотрудников |
| `security-test`, `security-ui` | пароли, сессии, резервная копия |
| `устройства-test` | **утёкший пароль не пускает**: вход только с разрешённых устройств |
| `attack-test`, `flood-test` | попытки взлома и наплыв запросов на вход |
| `domain-test`, `https-test` | работа за прокси, на домене, по https |
| `onboard-ui` | подключение сотрудника по QR-карточке |
| `workday-test` | рабочий день целиком, глазами продавца |
| `pwa-test`, `design-check` | установка на телефон, вёрстка |

## Наборы с браузером

Часть проверок открывает настоящий браузер — это единственный способ увидеть
то же, что видит продавец. Им нужен Playwright:

```bash
npm i -D playwright && npx playwright install chromium
```

Без него они честно помечаются как пропущенные, а остальные идут своим ходом.

## Один набор отдельно

Когда что-то упало и нужны подробности:

```bash
npm start                                        # в одном окне
BASE=http://127.0.0.1:3000 node тесты/roles-test.js   # в другом
```

## Порядок в `ПРОВЕРИТЬ.js` не случаен

`attack-test` и `flood-test` намеренно долбят вход неверными паролями, после
чего система на минуту закрывает вход — это её работа. Поэтому они стоят
последними: набор, запущенный сразу за ними, упал бы не по своей вине.
