# Проверки

Одна команда из папки с системой:

```bash
npm test
```

Она создаёт **отдельную** базу с демонстрационными данными (ваша рабочая база
не трогается), поднимает сервер на свободном порту, прогоняет все наборы
и печатает сводку.

Всё временное — снимки экрана, тестовые базы, папки обмена — складывается
в `тесты/.вывод` и в git не попадает.

## Зачем это здесь

Система считает деньги магазина. Почти всё в ней доказано не рассуждением,
а проверкой: продажа, возврат, обмен, долги перед поставщиками, комплекты,
права продавца, защита входа, обмен с 1С. Пока проверок нет рядом с кодом,
любая правка — и уж тем более переезд на другой хостинг — делается вслепую:
ошибки в деньгах не падают с сообщением, они молча дают неверную цифру.

## Наборы с браузером

Часть проверок открывает настоящий браузер — это единственный способ увидеть
то же, что видит продавец. Им нужен Playwright:

```bash
npm i -D playwright && npx playwright install chromium
```

Без него они честно помечаются как пропущенные, а остальные идут своим ходом.

## Один набор отдельно

Когда что-то упало и нужны подробности:

```bash
npm start                                        # в одном окне
BASE=http://127.0.0.1:3000 node тесты/roles-test.js   # в другом
```

## Порядок в `ПРОВЕРИТЬ.js` не случаен

`attack-test` и `flood-test` намеренно долбят вход неверными паролями, после
чего система на минуту закрывает вход — это её работа. Поэтому они стоят
последними: набор, запущенный сразу за ними, упал бы не по своей вине.
