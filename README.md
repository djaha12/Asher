# Asher — CRM-платформа для ювелирного магазина 💎

Собственная учётная система «всё в одном»: каталог изделий с ювелирной спецификой,
клиенты с личными скидками, продажи (POS) с рассрочкой и обменом, заказы и ремонт, финансы с P&L-отчётом,
аналитика и перенос данных из 1С.

Работает локально, данные хранятся у вас. Внешних зависимостей нет — нужен только Node.js.

## Быстрый старт

**Без командной строки**: читайте **[КАК-ЗАПУСТИТЬ.md](КАК-ЗАПУСТИТЬ.md)** —
инструкция в два клика. На Windows: `ДЕМО-ДАННЫЕ.bat`, затем `СТАРТ.bat`.
На Mac: `СТАРТ.command`.

Для тех, кто дружит с терминалом — [Node.js](https://nodejs.org) версии 22.5 или новее и:

```bash
# 1. Запустить систему
npm start

# 2. Открыть в браузере
#    http://localhost:3000
#    Вход: admin / admin123  (смените пароль в Настройках!)
```

Хотите посмотреть систему с демонстрационными данными (152 изделия, клиенты,
8 месяцев продаж, заказы, финансы)?

```bash
npm run seed     # наполнить пустую базу демо-данными
npm run reset    # полностью сбросить базу и наполнить заново
```

> ⚠️ Перед `npm run reset` остановите сервер (Ctrl+C) и запустите его заново после —
> иначе сервер продолжит работать со старой копией базы.

Демо-пользователи: `admin / admin123` (администратор), `anna / seller123` и
`mikhail / seller123` (продавцы).

## Возможности

### 📷 Фотографии изделий
- Каталог плитками с крупными фото — товар видно, а не читаешь список
- Четыре способа добавить: **массовая загрузка папки** (файлы названы артикулом),
  перетаскивание мышкой, выбор файлов, **съёмка камерой телефона**
- Несколько ракурсов на изделие, главное фото, просмотр во весь экран
- Уменьшение делает браузер: снимок с телефона на 8 МБ доезжает как 300 КБ
- Фильтр «без фото» — сразу видно, что осталось сфотографировать

### ⏳ Долги
**Клиенты должны нам.** При продаже указываете, сколько внесли сейчас, и срок
погашения — остаток становится долгом. Список должников с просрочкой, приём
оплаты (сумма гасит документы по очереди, от самого раннего срока), история
платежей, кнопка «написать в WhatsApp» с готовым текстом напоминания.
Возврат товара сначала гасит долг и только потом возвращает деньги из кассы.

**Мы должны поставщикам.** Книга расчётов по каждому поставщику: поставки,
оплаты, корректировки, текущий баланс и ближайший срок платежа.
**Возврат поставщику** (брак, пересорт, не продалось) уходит со склада отдельной
строкой и уменьшает долг на закупочную стоимость; вернули изделие на витрину —
долг восстановился. Поставщика с незакрытыми расчётами удалить нельзя.

**Товар на реализации.** Отмечаете изделие как чужое — и как только оно продано,
система сама записывает долг перед владельцем на закупочную стоимость.
Возврат покупателя этот долг снимает.

### 🏬 Несколько точек продаж
- Учёт остатков по каждой точке: изделий, в деньгах и в граммах
- Перемещение товара между точками пачкой, с историей
- Фильтры каталога, аналитики и инвентаризации по точке

### 📷 Чтение QR по фото
- Сфотографировали бирку — система нашла изделие: работает в кассе, обмене
  и инвентаризации, на любом телефоне (включая iPhone)
- В QR может быть артикул, штрихкод или ссылка — система сама извлечёт код
- Камера-сканер в инвентаризации теперь работает и без Chrome (движок jsQR)
- На печатаемые бирки можно добавить QR-код — и читать их потом любым телефоном

### 📋 Инвентаризация
- Сессия пересчёта по точке; сканировать можно обычным сканером штрихкодов,
  камерой телефона или вводя артикул руками
- В реальном времени: найдено / не найдено / лишнее (числится за другой точкой)
- Прогресс в процентах, стоимость недостачи, списание недостачи одной кнопкой

### 🏷 Ценники и бирки
- Печать пачкой на обычном принтере, штрихкод Code128 рисуется в браузере
- Настраиваемый состав бирки: название, артикул, металл, вес, цена, штрихкод
- Если своего штрихкода у изделия нет, кодируется артикул — и такая бирка
  потом читается сканером при продаже и инвентаризации

### 💍 Каталог изделий
- Заточен под бриллианты: **проба, каратность, цвет и чистота** — обычные поля
  изделия, а не спрятанные в списке вставок. Видны на плитке каталога, в списке,
  в карточке и на бирке
- Отбор по цвету и чистоте, сортировка по каратности; шкалы идут как принято —
  цвет от D, чистота от IF, а не по алфавиту
- Подсказки в форме короткие: золото 750-й пробы и бриллианты. Вписать своё
  значение можно всегда — поле остаётся обычным
- Металл и проба хранятся раздельно («Белое золото» + «750»), поэтому отбор
  по пробе работает точно
- **Сертификаты на камни**: лаборатория и номер (GIA, IGI, HRD) у конкретной вставки,
  файл сертификата — PDF с сайта лаборатории или фотография бумаги. Номер попадает
  в поиск: с бумажкой в руках изделие находится и в каталоге, и в кассе
- Артикулы и штрихкоды, поставщики, расположение (витрина/сейф)
- **Закупка в валюте**: цена в долларах и курс на момент закупки; в сомах хранится
  пересчитанная сумма, поэтому себестоимость и прибыль прошлых месяцев не меняются
  при скачке курса. Курс — в Настройках, подставляется сам
- Статусы: в наличии → резерв (за клиентом) → продано / списано, с причиной списания
- **Резерв со сроком**: отложили на 3 дня — по истечении система сама вернёт
  изделие на витрину и запишет это в журнал

### 💎 Комплекты (гарнитуры)
- Кольцо, серьги и подвеска одной позицией со своим названием, артикулом и ценой
- Продажа одним движением: разница между ценой комплекта и суммой изделий
  раскладывается по позициям скидкой, поэтому чек, возвраты и обмен работают как обычно
- Склад не задваивается: комплект — это объединение изделий, а не отдельный товар
- В любой момент разбирается обратно; если одно изделие продали отдельно,
  комплект помечается неполным
- Поиск, фильтры по категории, металлу, статусу, точке и наличию фото
- Сортировка по названию, артикулу и цене; история продаж и перемещений изделия

### 👤 Клиенты
- Персональные скидки — подставляются в чек автоматически
- Дни рождения и годовщины — виджет «Поводы связаться» на главной
- Размер кольца, предпочтения, заметки, полная история покупок и заказов

### ₽ Продажи (POS)
- Быстрое оформление: поиск изделия или **сканер штрихкодов** (ввод + Enter)
- Клиент, персональная скидка (подставляется сама), скидка на чек
- **Обмен изделия одним документом**: клиент возвращает одно и берёт другое,
  деньги за возвращённое идут в зачёт — доплачивается или выдаётся только разница
- Способы оплаты: наличные, карта, перевод, рассрочка
- **Оплата частями**: сколько внесли сейчас и до какого числа погасят остаток
- Печать товарного чека, возвраты (частичные и полные) с возвратом изделия на витрину

### 🛠 Заказы и ремонт
- Типы: ремонт, изготовление, гравировка, изменение размера, чистка, оценка
- Канбан-доска: принят → в работе → готов → выдан
- Предоплата при приёме, доплата при выдаче — всё попадает в финансы
- Сроки готовности с подсветкой просроченных

### 📒 Финансы
- Приходы и расходы по категориям (аренда, зарплата, налоги, закупка…)
- Продажи, возвраты и оплаты заказов записываются автоматически
- **Отчёт о прибылях и убытках (P&L)** по месяцам: выручка, себестоимость,
  валовая и чистая прибыль, расходы по категориям

### 📈 Аналитика
- Выручка и прибыль по дням/месяцам, средний чек, маржа, возвраты
- Разрезы: категории, металлы, продавцы, способы оплаты
- Топ продаж и лучшие клиенты
- Склад: остатки в деньгах и в граммах металла, залежавшиеся изделия

### ⇄ Импорт из 1С и экспорт
- **Автообмен через папку**: положите CSV-выгрузку из 1С в папку `1С-ОБМЕН`
  рядом с программой — система сама обновит цены, добавит новые позиции и
  переложит файл в «обработано» с текстовым отчётом. Ничего нажимать не нужно
- Импорт номенклатуры и контрагентов из CSV-выгрузок 1С
  (пошаговая инструкция прямо на странице импорта)
- **Повторная выгрузка**: изделия сопоставляются по артикулу, цены обновляются,
  новые позиции добавляются. Вы сами выбираете, какие поля перезаписывать;
  проданное и списанное не трогается
- **Прайс-лист для переоценки**: файла из двух колонок — артикул и цена — достаточно.
  Наименования не нужны: система найдёт изделия по артикулу и проставит новые цены,
  ничего не создавая. Артикулы, которых нет в каталоге, перечисляются в отчёте.
  Так же работает и папка автообмена
- **Перенос фотографий папкой**: файлы, названные артикулом, раскладываются
  по изделиям автоматически
- Автоопределение кодировки (UTF-8 / Windows-1251), разделителя (`;` `,` таб)
  и соответствия колонок («Наименование» → название, «Розничная цена» → цена…)
- Числа распознаются в любом формате: и «12 345,67» из 1С, и «12,345.67» из Excel;
  подпись валюты в ячейке не мешает. Даты — «31.12.1985» и «1985-12-31»
- Экспорт изделий, клиентов и продаж в CSV (открывается в Excel)

### 🌍 Страна и валюта
- Готовые наборы: **Кыргызстан** (по умолчанию), Казахстан, Узбекистан, Таджикистан,
  Россия, Беларусь, Армения, Азербайджан, Грузия, Турция, ОАЭ
- Выбрали страну — подставились валюта, формат сумм и телефонный код;
  любое поле потом правится вручную
- Суммы в сомах, тенге и сумах показываются без копеек: «45 000 сом», а не «45 000,00»
- Телефон клиента можно записывать как угодно — «0555 12-34-56», «+996 555 123456»,
  «555123456»: для WhatsApp номер приводится к международному виду сам,
  а номер гостя из другой страны остаётся как есть

### 📱 Работа с телефона
- Система запускается на компьютере, телефон открывает её по Wi-Fi магазина
- Адрес для телефона печатается при запуске и показан в Настройках — с кнопкой «Копировать»
- Добавьте страницу на главный экран телефона, и она будет открываться как приложение

### Дополнительно
- **Светлая и тёмная темы** с переключателем; крупный шрифт и большие кнопки —
  система рассчитана на долгую работу за прилавком
- **Работает с телефона**: нижняя навигация, каталог с фото, долги, сканирование
- **Две роли — два вида системы**: администратор видит всё; продавец работает
  за прилавком (каталог, продажи, обмены, клиенты, долги, заказы,
  инвентаризация, бирки), но закупочных цен, наценки, прибыли, расчётов с
  поставщиками, финансов, аналитики и журнала не видит. Закупочная цена скрыта
  и на чтение, и на запись: правка изделия продавцом её не затирает
- **Журнал операций**: кто, что и когда сделал в системе
- Защита от продажи одного изделия дважды, от удаления изделий с историей продаж

## Технически

| | |
|---|---|
| Сервер | Node.js (встроенные модули, без npm-пакетов) |
| База данных | SQLite — файл `data/asher.db` (встроенный `node:sqlite`) |
| Интерфейс | SPA на чистом HTML/CSS/JS, язык — русский, светлая и тёмная темы |
| Фотографии | файлы в `data/images`, уменьшение — на стороне браузера |
| Авторизация | Сессии в cookie, пароли — scrypt с солью |
| Локаль | Валюта, формат сумм и телефонов — в настройках, наборы стран в `src/locale.js` |

```
server.js          — HTTP-сервер и маршрутизация API
src/db.js          — схема базы данных
src/locale.js      — валюта, телефоны и форматы по странам
src/seed.js        — демо-данные
src/api/*.js       — модули API (товары, фото, клиенты, продажи, долги, точки,
                     инвентаризация, заказы, финансы, аналитика, импорт)
public/            — интерфейс (страницы в public/js/pages/)
data/asher.db      — ваша база (создаётся автоматически, в git не попадает)
data/images/       — фотографии изделий
```

**Резервные копии** — делаются сами: раз в сутки целостный снимок базы
(`VACUUM INTO`) сохраняется в папку `РЕЗЕРВНЫЕ-КОПИИ`, хранятся последние 14.
Полная копия вручную — папка `data` целиком (при остановленном сервере): в ней
и база, и фотографии. Отдельно можно выгрузить CSV со страницы «Импорт из 1С».

**Смена порта**: `ASHER_PORT=8080 npm start`.

**Открыть с телефона**: запустите систему на компьютере и наберите на телефоне адрес,
который она напечатает при старте (вида `http://192.168.1.5:3000`). Телефон должен быть
в той же сети Wi-Fi. Тот же адрес есть в Настройках → Магазин.

> Система рассчитана на работу внутри магазина (локально или в вашей внутренней
> сети). Не публикуйте её напрямую в интернет без HTTPS-прокси и сильных паролей.
