# Asher — CRM-платформа для ювелирного магазина 💎

Собственная учётная система «всё в одном»: каталог изделий с ювелирной спецификой,
клиенты с личными скидками, продажи (POS) с рассрочкой и обменом, заказы и ремонт, финансы с P&L-отчётом,
аналитика и перенос данных из 1С.

Работает локально, данные хранятся у вас. Внешних зависимостей нет — нужен только Node.js.

## Быстрый старт

**Без командной строки**: читайте **[КАК-ЗАПУСТИТЬ.md](КАК-ЗАПУСТИТЬ.md)** —
инструкция в два клика. На Windows: `ДЕМО-ДАННЫЕ.bat`, затем `СТАРТ.bat`.
На Mac: `СТАРТ.command`.

Для тех, кто дружит с терминалом — [Node.js](https://nodejs.org) версии 22.5 или новее и:

```bash
# 1. Запустить систему
npm start

# 2. Открыть в браузере
#    http://localhost:3000
#    Вход: admin / admin123  (смените пароль в Настройках!)
```

Хотите посмотреть систему с демонстрационными данными (152 изделия, клиенты,
8 месяцев продаж, заказы, финансы)?

```bash
npm run seed     # наполнить пустую базу демо-данными
npm run reset    # полностью сбросить базу и наполнить заново
```

> ⚠️ Перед `npm run reset` остановите сервер (Ctrl+C) и запустите его заново после —
> иначе сервер продолжит работать со старой копией базы.

Прогнать все проверки (создаётся отдельная база, рабочая не трогается):

```bash
npm test
```

Подробности — в [тесты/README.md](тесты/README.md).

Сброс пароля, когда войти не получается (и при установке на сервер) — команда
печатает новый пароль:

```bash
node src/пароль.js admin            # придумает и напечатает
node src/пароль.js admin «свой»     # поставит заданный
```

Демо-пользователи: `admin / admin123` (администратор), `anna / seller123` и
`mikhail / seller123` (продавцы).

## Возможности

### 📷 Фотографии изделий
- Каталог плитками с крупными фото — товар видно, а не читаешь список
- Четыре способа добавить: **массовая загрузка папки** (файлы названы артикулом),
  перетаскивание мышкой, выбор файлов, **съёмка камерой телефона**
- Несколько ракурсов на изделие, главное фото, просмотр во весь экран
- Уменьшение делает браузер: снимок с телефона на 8 МБ доезжает как 300 КБ
- Фильтр «без фото» — сразу видно, что осталось сфотографировать

### ⏳ Долги
**Клиенты должны нам.** При продаже указываете, сколько внесли сейчас, и срок
погашения — остаток становится долгом. Список должников с просрочкой, приём
оплаты (сумма гасит документы по очереди, от самого раннего срока), история
платежей, кнопка «написать в WhatsApp» с готовым текстом напоминания.
Возврат товара сначала гасит долг и только потом возвращает деньги из кассы.

**Мы должны поставщикам.** Книга расчётов по каждому поставщику: поставки,
оплаты, корректировки, текущий баланс и ближайший срок платежа.
**Возврат поставщику** (брак, пересорт, не продалось) уходит со склада отдельной
строкой и уменьшает долг на закупочную стоимость; вернули изделие на витрину —
долг восстановился. Поставщика с незакрытыми расчётами удалить нельзя.

**Товар на реализации.** Отмечаете изделие как чужое — и как только оно продано,
система сама записывает долг перед владельцем на закупочную стоимость.
Возврат покупателя этот долг снимает.

### 🏬 Несколько точек продаж
- Учёт остатков по каждой точке: изделий, в деньгах и в граммах
- Перемещение товара между точками пачкой, с историей
- Фильтры каталога, аналитики и инвентаризации по точке

### 📷 Чтение QR по фото
- Сфотографировали бирку — система нашла изделие: работает в кассе, обмене
  и инвентаризации, на любом телефоне (включая iPhone)
- В QR может быть артикул, штрихкод или ссылка — система сама извлечёт код
- Камера-сканер в инвентаризации теперь работает и без Chrome (движок jsQR)
- На печатаемые бирки можно добавить QR-код — и читать их потом любым телефоном

### 📋 Инвентаризация
- Сессия пересчёта по точке; сканировать можно обычным сканером штрихкодов,
  камерой телефона или вводя артикул руками
- В реальном времени: найдено / не найдено / лишнее (числится за другой точкой)
- Прогресс в процентах, стоимость недостачи, списание недостачи одной кнопкой

### 🏷 Ценники и бирки
- Печать пачкой на обычном принтере, штрихкод Code128 рисуется в браузере
- Настраиваемый состав бирки: название, артикул, металл, вес, цена, штрихкод
- Если своего штрихкода у изделия нет, кодируется артикул — и такая бирка
  потом читается сканером при продаже и инвентаризации

### 💍 Каталог изделий
- Заточен под бриллианты: **проба, каратность, цвет и чистота** — обычные поля
  изделия, а не спрятанные в списке вставок. Видны на плитке каталога, в списке,
  в карточке и на бирке
- Отбор по цвету и чистоте, сортировка по каратности; шкалы идут как принято —
  цвет от D, чистота от IF, а не по алфавиту
- Подсказки в форме короткие: золото 750-й пробы и бриллианты. Вписать своё
  значение можно всегда — поле остаётся обычным
- Металл и проба хранятся раздельно («Белое золото» + «750»), поэтому отбор
  по пробе работает точно
- **Сертификаты на камни**: лаборатория и номер (GIA, IGI, HRD) у конкретной вставки,
  файл сертификата — PDF с сайта лаборатории или фотография бумаги. Номер попадает
  в поиск: с бумажкой в руках изделие находится и в каталоге, и в кассе
- **Паспорт изделия** — лист, который покупатель уносит с украшением: фото,
  металл с пробой, вес, размер, все вставки с характеристиками, сертификат
  и QR проверки на сайте GIA/IGI, дата и номер чека. Цена — по галочке (паспорт
  часто уходит с подарком). QR внизу — код изделия: касса читает его камерой,
  когда изделие приносят обратно. Печать или отправка клиенту в WhatsApp —
  из карточки изделия или сразу для всех изделий чека
- Артикулы и штрихкоды, поставщики, расположение (витрина/сейф)
- **Закупка в валюте**: цена в долларах и курс на момент закупки; в сомах хранится
  пересчитанная сумма, поэтому себестоимость и прибыль прошлых месяцев не меняются
  при скачке курса. Курс — в Настройках, подставляется сам
- Статусы: в наличии → резерв (за клиентом) → продано / списано, с причиной списания
- **Резерв со сроком**: отложили на 3 дня — по истечении система сама вернёт
  изделие на витрину и запишет это в журнал

### 💎 Комплекты (гарнитуры)
- Кольцо, серьги и подвеска одной позицией со своим названием, артикулом и ценой
- Продажа одним движением: разница между ценой комплекта и суммой изделий
  раскладывается по позициям скидкой, поэтому чек, возвраты и обмен работают как обычно
- Склад не задваивается: комплект — это объединение изделий, а не отдельный товар
- В любой момент разбирается обратно; если одно изделие продали отдельно,
  комплект помечается неполным
- Поиск, фильтры по категории, металлу, статусу, точке и наличию фото
- Сортировка по названию, артикулу и цене; история продаж и перемещений изделия

### 🔎 Поиск по всей системе
- Одно поле в шапке вместо восьми по разделам: артикул, штрихкод, имя клиента,
  телефон в любой записи («0700 495», «+996700495», «4952573»), номер чека,
  номер заказа, номер сертификата, название комплекта
- Находки сгруппированы по разделам, выбор ведёт прямо в карточку;
  Ctrl+K открывает, стрелки выбирают, Enter открывает
- На телефоне раскрывается на весь экран по значку лупы

### 📤 Изделие клиенту в WhatsApp
- Кнопка «Клиенту» в карточке: готовое сообщение с артикулом, металлом и пробой,
  каратностью/цветом/чистотой, весом, размером и ценой
- Получателя можно выбрать из базы клиентов — откроется переписка именно с ним
- С телефона фотография уходит вместе с текстом (через «Поделиться»),
  с компьютера — текст, который можно скопировать одной кнопкой
- Закупочная цена в сообщение не попадает

### ⚖️ Цена от грамма
- Задайте в Настройках цену грамма и работу за грамм — в форме изделия появится
  расчёт «вес × (цена грамма + работа)»; стоимость камня добавляется вручную
- Поле цены остаётся обычным: посчитанное значение можно поправить
- Цена хранится готовой суммой, поэтому смена цены грамма не переписывает
  задним числом ни ценники, ни прошлые чеки
- Поля не заполнены — кнопки нет, ничего не меняется

### 📦 Приёмка от поставщика
- Накладная одним экраном: выбрали поставщика, вбили строки — товар встал
  на склад, а **долг перед поставщиком записался сам** и ровно на сумму принятого
- Наценка одной кнопкой проставляет цены продажи по всей накладной
- Закупка в долларах: курс запоминается на момент поставки
- Товар на реализации принимается так же, но долг появится только при продаже
- Каждое изделие помнит, из какой накладной пришло: на вопрос «что было
  в поставке от 3 марта» есть ответ
- Ошибка в любой строке отменяет всю накладную: половины принятой поставки
  не бывает

### 👤 Клиенты
- Персональные скидки — подставляются в чек автоматически
- **Новый клиент прямо в кассе**: поиск не нашёл — тут же заводите по имени
  и телефону, не бросая набранный чек
- **Откуда пришёл**: Instagram, WhatsApp, сарафанное радио, TikTok, 2ГИС,
  проходили мимо — одним нажатием прямо при заведении клиента; фильтр в списке
  клиентов и разбор в аналитике
- **Поводы связаться** на главной: дни рождения и годовщины, «спасибо за покупку»
  через пару дней, приглашение почистить изделие через полгода — у каждого
  WhatsApp с готовым текстом; кому написали, пропадает у всех продавцов
- **Номер ищется, как его ни набери**: «0555123456» находит «+996 555 12-34-56»
- **Без дублей**: тот же номер второй раз не заводится молча — система
  предлагает выбрать клиента, который уже есть (или всё равно завести, если
  номер общий на семью)
- **Из карточки клиента**: WhatsApp, звонок, долг и «Принять оплату»,
  «Хочет» — чего человек спрашивал и не нашёл, чтобы позвонить, когда появится
- Размер кольца, предпочтения, заметки, полная история покупок и заказов

### ₽ Продажи (POS)
- Быстрое оформление: поиск изделия или **сканер штрихкодов** (ввод + Enter)
- Клиент, персональная скидка (подставляется сама), скидка на чек
- **Потолок скидки для продавца** (Настройки, по умолчанию 15%): изделие
  не уйдёт за бесценок ни по злому умыслу, ни по опечатке. Владелец не ограничен,
  но его скидки сверх предела попадают в журнал отдельной строкой
- **Скидка сверх предела — по разрешению владельца**: продавец нажимает
  «Попросить владельца» прямо в кассе, владелец видит запрос у себя на Главной
  (кто, что, сколько процентов и почему) и отвечает «Разрешить» или «Отказать».
  Разрешённая скидка сама встаёт в чек. Разрешение — только этому продавцу,
  на эти изделия, не больше разрешённого, один раз и на 30 минут
- **Обмен изделия одним документом**: клиент возвращает одно и берёт другое,
  деньги за возвращённое идут в зачёт — доплачивается или выдаётся только разница
- **Старое золото в зачёт покупки**: взвесили, выбрали пробу — касса сразу
  показывает оценку (вес × цена грамма) и «К доплате». Цену грамма 585-й пробы
  задаёт владелец в Настройках, другие пробы — пропорционально золоту в них;
  продавец цену не меняет. Зачёт — не деньги: в ящик не ложится и прибыль в отчёте
  не меняет; зачёт не больше покупки (разницу деньгами система не выдаёт).
  Имя клиента обязательно — оно в **акте приёма** с весом, пробой, чистым золотом
  и подписями, два экземпляра. Раздел «Старое золото»: сколько граммов какой пробы
  накоплено и все акты. Если такой чек потом вернут, деньгами возвращается и
  зачтённая часть — золото остаётся у магазина
- Способы оплаты: наличные, карта, перевод, рассрочка; при рассрочке касса
  спрашивает, чем внесли первый взнос
- **Оплата частями**: сколько внесли сейчас и до какого числа погасят остаток
- Печать товарного чека, возвраты (частичные и полные) с возвратом изделия на витрину

### 🛠 Заказы и ремонт
- Типы: ремонт, изготовление, гравировка, изменение размера, чистка, оценка
- Канбан-доска: принят → в работе → готов → выдан
- Предоплата при приёме, доплата при выдаче — всё попадает в финансы;
  в каждом окне оплаты — «чем платят»: наличные, карта или перевод. Картой и
  переводом деньги в ящик не ждутся, и сверка кассы не показывает ложную недостачу
- Сроки готовности с подсветкой просроченных
- **Приём по-взрослому**: изделие, вес при приёме («4,52» с запятой — как на
  весах), камни, дефекты и фото с телефона — спор «было три камня, а стало два»
  решает квитанция, а не слово против слова
- **Квитанция** сразу после приёма: два экземпляра на одном листе (клиенту
  и магазину) с местами для подписей — или в WhatsApp клиенту, если принтера нет
- **«Готов» одним нажатием** прямо на карточке — из «Принят» или «В работе»;
  тут же предлагается написать клиенту в WhatsApp «заказ готов, к оплате …».
  Кому написали — видно всем; отмеченный по ошибке возвращается в работу
- При выдаче — напоминание взвесить изделие при клиенте
- Фото при приёме удаляет только владелец или бухгалтер: это доказательство;
  фото попадают в резервную копию

### 📒 Финансы
- Приходы и расходы по категориям (аренда, зарплата, налоги, закупка…)
- Продажи, возвраты и оплаты заказов записываются автоматически
- **Отчёт о прибылях и убытках (P&L)** по месяцам: выручка, себестоимость,
  валовая и чистая прибыль, расходы по категориям
- **Сводка за день** на Главной у владельца: сколько продали и кто, как пришли
  деньги, сошлась ли касса (недостача — с именем), скидки сверх предела,
  возвраты, ремонт, новые клиенты. «Вчера» или «Сегодня», и одним нажатием —
  в WhatsApp себе или партнёру
- **Сверка кассы**: система сама считает, сколько наличных должно быть в ящике,
  продавец вводит пересчитанное — недостача или излишек видны в тот же вечер
- **«Сдать владельцу» и «Внести размен»** прямо из окна сверки. Это не расход
  и не доход: деньги перешли из ящика в руки владельца, отчёт о прибыли их
  не «теряет». Сдачу подтверждает тот, кому отдали: у него на Главной —
  «Деньги у меня» или «Не получено»; отметка не переделывается
- **Сдача смены**: уходящий продавец пересчитывает ящик и сдаёт смену,
  следующий на своём входе видит «Смену сдаёт Анна: в ящике …», пересчитывает
  вместе и принимает. Свою смену принять нельзя; расхождение между ними
  записывается, пока оба у ящика; брошенная смена видна владельцу в Финансах

### 📈 Аналитика
- Выручка и прибыль по дням/месяцам, средний чек, маржа, возвраты
- Разрезы: категории, металлы, продавцы, способы оплаты
- **Откуда приходят клиенты**: сколько новых пришло из Instagram, WhatsApp,
  по сарафанному радио и сколько денег принесли клиенты из каждого источника
- Топ продаж и лучшие клиенты
- Склад: остатки в деньгах и в граммах металла, залежавшиеся изделия

### ⇄ Импорт из 1С и экспорт
- **Автообмен через папку**: положите CSV-выгрузку из 1С в папку `1С-ОБМЕН`
  рядом с программой — система сама обновит цены, добавит новые позиции и
  переложит файл в «обработано» с текстовым отчётом. Ничего нажимать не нужно
- Импорт номенклатуры и контрагентов из CSV-выгрузок 1С
  (пошаговая инструкция прямо на странице импорта)
- **Повторная выгрузка**: изделия сопоставляются по артикулу, цены обновляются,
  новые позиции добавляются. Вы сами выбираете, какие поля перезаписывать;
  проданное и списанное не трогается
- **Прайс-лист для переоценки**: файла из двух колонок — артикул и цена — достаточно.
  Наименования не нужны: система найдёт изделия по артикулу и проставит новые цены,
  ничего не создавая. Артикулы, которых нет в каталоге, перечисляются в отчёте.
  Так же работает и папка автообмена
- **Перенос фотографий папкой**: файлы, названные артикулом, раскладываются
  по изделиям автоматически
- Автоопределение кодировки (UTF-8 / Windows-1251), разделителя (`;` `,` таб)
  и соответствия колонок («Наименование» → название, «Розничная цена» → цена…)
- Числа распознаются в любом формате: и «12 345,67» из 1С, и «12,345.67» из Excel;
  подпись валюты в ячейке не мешает. Даты — «31.12.1985» и «1985-12-31»
- Экспорт изделий, клиентов и продаж в CSV (открывается в Excel)

### 🌍 Страна и валюта

### 📱 Работа с телефона
- Система запускается на компьютере, телефон открывает её по Wi-Fi магазина
- Адрес для телефона печатается при запуске и показан в Настройках — с кнопкой «Копировать»

### Дополнительно
- **Светлая и тёмная темы** с переключателем; крупный шрифт и большие кнопки —
  система рассчитана на долгую работу за прилавком
- **Работает с телефона**: нижняя навигация, каталог с фото, долги, сканирование
- **Три роли — три вида системы**: основатель видит всё, включая панель
  основателя (кто когда входил, кто что продал, скидки, удаления, лента
  действий) и журнал; бухгалтер видит и делает всё то же, кроме этой панели,
  журнала и учётной записи основателя; продавец работает за прилавком
  (каталог, продажи, обмены, клиенты, долги, заказы, инвентаризация, бирки),
  но закупочных цен, наценки, прибыли, расчётов с поставщиками, финансов и
  аналитики не видит. Закупочная цена скрыта и на чтение, и на запись:
  правка изделия продавцом её не затирает
- **Вход только с разрешённых устройств**: верного пароля недостаточно.
  Незнакомое устройство получает экран ожидания с кодом, а войти сможет лишь
  после того, как владелец разрешит его — прямо на Главной, одним нажатием:
  там видно, кто просится, и тот же код, что у сотрудника на экране. Первое
  устройство каждого сотрудника доверяется само — иначе разрешать было бы
  некому. Отклонение устройства немедленно обрывает все входы этого
  сотрудника. Возврат доступа при утере устройства — только с сервера:
  `node src/пароль.js admin` заодно забывает устройства
- **Безопасность** (Настройки → Безопасность): состояние защиты одной
  страницей, скачивание резервной копии, список устройств. Подбор пароля
  останавливается по логину (5 промахов — минута, дальше до двух часов), при
  этом остальные сотрудники продолжают работать; смена пароля и отключение
  сотрудника обрывают его вход на всех устройствах; заголовки CSP/HSTS,
  cookie HttpOnly + SameSite + Secure по https. Готовность к работе в интернете
  описана в [ХОСТИНГ.md](ХОСТИНГ.md)
- **Журнал действий** (Настройки → Журнал действий): каждое действие каждого
  сотрудника — продажи, возвраты и обмены, приём оплаты, резервы и списания
  с причиной, правки изделий, входы в систему. Отбор по сотруднику, виду
  действия, датам и поиску по деталям; сводка «кто сколько сделал»; записи
  не редактируются и не удаляются
- **Одна база на все устройства**: ноутбук и телефоны видят одно и то же
  в ту же секунду; одно изделие нельзя продать дважды даже при одновременной
  продаже с двух телефонов
- Защита от продажи одного изделия дважды, от удаления изделий с историей продаж

## Технически

| | |
|---|---|
| Сервер | Node.js (встроенные модули, без npm-пакетов) |
| База данных | SQLite — файл `data/asher.db` (встроенный `node:sqlite`) |
| Интерфейс | SPA на чистом HTML/CSS/JS, язык — русский, светлая и тёмная темы |
| Фотографии | файлы в `data/images`, уменьшение — на стороне браузера |
| Авторизация | Сессии в cookie, пароли — scrypt с солью |
| Локаль | Валюта, формат сумм и телефонов — в настройках, наборы стран в `src/locale.js` |

```
server.js          — HTTP-сервер и маршрутизация API
src/db.js          — схема базы данных
src/locale.js      — валюта, телефоны и форматы по странам
src/seed.js        — демо-данные
src/api/*.js       — модули API (товары, фото, клиенты, продажи, долги, точки,
                     инвентаризация, заказы, финансы, аналитика, импорт)
public/            — интерфейс (страницы в public/js/pages/)
data/asher.db      — ваша база (создаётся автоматически, в git не попадает)
data/images/       — фотографии изделий
```

**Резервные копии** — делаются сами: раз в сутки целостный снимок базы
(`VACUUM INTO`) сохраняется в папку `РЕЗЕРВНЫЕ-КОПИИ`, хранятся последние 14.
Полная копия одной кнопкой — Настройки → Безопасность → «Скачать резервную
копию»: отдаётся ZIP со снимком базы и всей папкой `data/images`. Восстановление —
распаковать поверх папки системы, заменив `data` (сервер при этом остановлен,
файлы `asher.db-wal`/`-shm` удалить). Отдельно можно выгрузить CSV со страницы
«Импорт из 1С».

**Копия на другой компьютер, без участия человека.** Настройки → Безопасность →
«Копия сама, каждый день» выдаёт ключ, и тогда `GET /api/backup/download?key=…`
отдаёт тот же архив без сессии. Это единственный ответ системы без пароля:
ключ 160-битный, сравнивается за постоянное время, неудачные попытки идут через
ту же защиту, что и подбор пароля, каждое скачивание попадает в журнал действий,
а сам ключ не возвращается ни в одном ответе и отзывается одной кнопкой.
На Windows расписание заводит `КОПИЯ-КАЖДЫЙ-ДЕНЬ.bat` (вся работа —
в `src/backup-windows.ps1`): ежедневная задача, последние 14 архивов, журнал
рядом с ними.

**Смена порта**: `ASHER_PORT=8080 npm start`.

**Открыть с телефона**: запустите систему на компьютере и наберите на телефоне адрес,
который она напечатает при старте (вида `http://192.168.1.5:3000`). Телефон должен быть
в той же сети Wi-Fi. Тот же адрес есть в Настройках → Магазин.

> Система рассчитана на работу внутри магазина (локально или в вашей внутренней
> сети). Не публикуйте её напрямую в интернет без HTTPS-прокси и сильных паролей.
