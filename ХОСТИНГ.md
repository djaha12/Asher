# Asher в интернете

Здесь описано, как перенести систему с вашего компьютера на сервер в интернете:
телефоны начнут работать откуда угодно, компьютер можно будет выключать,
а на Android появится настоящая установка приложения в одно нажатие.

> **Быстрый путь.** Всё описанное ниже делает один скрипт. На чистом сервере
> Ubuntu, от root, одной строкой:
>
> ```bash
> curl -sL https://raw.githubusercontent.com/djaha12/Asher/HEAD/install.sh | bash -s diamonds.kg
> ```
>
> Она забирает систему с GitHub и запускает установщик `УСТАНОВКА-НА-СЕРВЕР.sh`.
> Английская она не для красоты: в консоли хостинга, открытой в браузере,
> нет ни вставки, ни русской раскладки.
>
> Пошаговая инструкция для владельца — в [ПЕРЕЕЗД-НА-ДОМЕН.md](ПЕРЕЕЗД-НА-ДОМЕН.md).
> Этот файл — описание того, что скрипт делает, и справочник, если настраивать руками.

Инструкция для того, кто будет настраивать сервер. Владельцу магазина читать
не обязательно — достаточно последнего раздела «Что изменится для вас».

## Что понадобится

| | Зачем | Примерно |
|---|---|---|
| VPS, 1 ядро / 1 ГБ памяти / 20 ГБ диска | на нём живёт система | 500–800 сом/мес |
| Доменное имя | чтобы вместо цифр был адрес | 1 000–1 500 сом/год |
| Сертификат https | шифрование | бесплатно, ставится сам |

Больше ничего: система не требует ни базы данных отдельно, ни внешних
библиотек — только Node.js 22.5 или новее.

### Откуда взялись эти цифры

Не на глаз — замерено на базе, набитой под три года работы магазина
(10 000 изделий, 15 000 продаж, 60 000 строк журнала) и 313 МБ фотографий:

| | Замерено |
|---|---|
| Память в покое | 59 МБ |
| Память под нагрузкой + скачивание резервной копии | **111 МБ** — самый тяжёлый момент |
| Самый медленный экран | 70 мс (журнал действий) |
| База за три года | 20 МБ |

То есть **1 ГБ памяти — с восьмикратным запасом**, а не впритык. Платить
за 4 ГБ незачем.

По диску считайте так: система с Ubuntu займёт около 6 ГБ, база вырастет
до сотни мегабайт, резервных копий система хранит 14 штук (только база,
без фотографий). Всё остальное — фотографии изделий: 2 000 изделий по три
снимка это примерно 2,5 ГБ. **20 ГБ хватит на годы, 40 ГБ — с запасом.**

## Установка

### 1. Node.js и сама система

```bash
# Ubuntu 24.04
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

sudo useradd -m -s /bin/bash asher
sudo -u asher git clone <адрес репозитория> /home/asher/app
```

### 2. Служба, которая поднимается сама

`/etc/systemd/system/asher.service`:

```ini
[Unit]
Description=Asher CRM
After=network.target

[Service]
Type=simple
User=asher
WorkingDirectory=/home/asher/app
Environment=PORT=3000
Environment=NO_OPEN=1
Environment=ASHER_STRICT_PORT=1
Environment=ASHER_TRUST_PROXY=1
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now asher
```

**`ASHER_STRICT_PORT=1` тоже обязателен.** Без него система при занятом порте
молча переезжает на соседний (удобно на домашнем компьютере, вредно здесь):
прокси продолжает стучаться в 3000, служба числится «активной», а сайт отдаёт
502 при полностью исправной системе. С этой переменной она честно не
запустится и напишет причину в журнал.

**`ASHER_TRUST_PROXY=1` обязателен.** Без него система считает, что все
посетители пришли с одного адреса — адреса прокси. Тогда в журнале вместо
настоящих адресов будет `127.0.0.1`, а защита от подбора пароля станет считать
весь интернет одним посетителем. И наоборот: **не включайте эту переменную,
когда система работает без прокси** — иначе адрес подделает кто угодно.

### 2.5. DNS: не покупайте платную услугу у регистратора

В панели cctld.kg вкладка «Услуга DNS» стоит 871 сом, но она не нужна: там же
написано, что при наличии хостинга достаточно указать NS-серверы провайдера.
Но у голого VPS DNS-панели с зоной домена, как правило, НЕТ — её дают
к виртуальному хостингу. Поэтому основной путь: Cloudflare (бесплатно, работает
с любым хостингом). Порядок строго такой:

1. Завести зону `diamonds.kg` в Cloudflare и создать в ней записи `A` (@ и www)
   на IP сервера, режим **DNS only** (серое облачко — с проксированием
   сертификат выдаётся сложнее).
2. Только после этого заменить в cctld.kg («Редактировать доменное имя»)
   `DAP/DAS.ASIAINFO.KG` на выданные Cloudflare NS. Поля «NS IP» оставить
   пустыми — они нужны только для NS-серверов внутри зоны .kg.

Обратный порядок ломает домен полностью: старые NS его уже не обслуживают,
а новые о нём не знают. Расхождение NS по интернету занимает до суток.

### 3. https и прокси

Caddy получает и продлевает сертификат сам. `/etc/caddy/Caddyfile`:

```
diamonds.kg {
    reverse_proxy 127.0.0.1:3000
}
```

```bash
sudo systemctl reload caddy
```

Caddy сам передаёт `X-Forwarded-Proto` и `X-Forwarded-For` — то, чего ждёт
`ASHER_TRUST_PROXY=1`.

Если используете nginx, эти заголовки надо передать вручную:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 30m;   # фотографии изделий
}
```

### 4. Закрыть порт системы снаружи

Снаружи должны быть доступны только 80 и 443. Порт 3000 — только изнутри
сервера, иначе к системе можно будет прийти мимо https.

```bash
sudo ufw allow 80,443/tcp
# Порт входа на сервер — свой у каждого хостинга, не считайте, что это 22:
ss -lntp | awk '/sshd/ {split($4,a,":"); print a[length(a)]}' | sort -u \
  | xargs -I{} sudo ufw allow {}/tcp
sudo ufw enable
```

### 5. Перенести данные

Переезжает всё: изделия, продажи, клиенты, долги, журнал и фотографии.
Порядок обязателен — иначе потеряются последние операции.

**На компьютере магазина.** Закройте систему через Ctrl+C (не крестиком) и
проверьте, что рядом с `data/asher.db` не осталось `asher.db-wal`. Если он есть,
в нём лежат последние продажи, которых в базе ещё нет: запустите систему заново
и закройте её Ctrl+C.

**На сервере.** Остановите службу и уберите её собственные `-wal`/`-shm` —
иначе новая база будет прочитана вместе с остатками старой:

```bash
sudo systemctl stop asher
sudo rm -f /home/asher/app/data/asher.db-wal /home/asher/app/data/asher.db-shm
```

**Копирование** (из папки с системой на компьютере магазина):

```bash
scp data/asher.db root@сервер:/home/asher/app/data/asher.db
scp -r data/images/. root@сервер:/home/asher/app/data/images/
```

**После копирования** вернуть права — файлы приехали от `root`, а служба
работает от `asher` и без этого не сможет писать:

```bash
sudo chown -R asher:asher /home/asher/app/data
sudo systemctl start asher
```

### 6. Резервные копии на другой сервер

Система и сама снимает копию раз в сутки в папку `РЕЗЕРВНЫЕ-КОПИИ`, но она
лежит на том же диске. Настройте выгрузку наружу — например, ежедневным
заданием:

```bash
0 4 * * * /usr/bin/rclone copy /home/asher/app/РЕЗЕРВНЫЕ-КОПИИ remote:asher-backup
```

Владелец в любой момент может забрать копию сам: Настройки → Безопасность →
«Скачать резервную копию».

### 7. Адреса для телефонов подставятся сами

Отдельно ничего настраивать не нужно: карточки подключения сотрудников
(Настройки → Сотрудники → 📱) и раздел «Открыть на телефоне» берут адрес
из строки браузера. Пока система в магазине — это адрес компьютера в Wi-Fi,
после переезда — `https://diamonds.kg`.

**Старые карточки с адресом `192.168…` перестанут работать** — раздайте
сотрудникам новые.

### 8. Сразу после запуска

1. **Сменить пароль `admin` — до всего остального.** Система уже открыта
   из интернета, а вместе с базой на сервер приехали пароли с компьютера
   магазина; если там был стандартный `admin123`, войти может кто угодно.
   Выдать новый прямо на сервере (команда напечатает его):

   ```bash
   cd /home/asher/app && sudo -u asher node src/пароль.js admin
   ```

   Затем войти с ним и поставить свой: Настройки → Мой пароль.
2. Проверить Настройки → Безопасность: все строки должны быть зелёными.
3. Раздать сотрудникам новые карточки подключения (Настройки → Сотрудники → 📱)
   — в них будет уже новый адрес.

## Что система делает для защиты

Всё это работает само, настраивать не нужно:

- **Пароли** хранятся не в открытом виде, а свёрткой scrypt со своей солью
  у каждого сотрудника.
- **Подбор пароля**: по логину — 5 промахов подряд закрывают вход на минуту,
  дальше 5 минут, 30 минут, 2 часа. По адресу порог намеренно высокий (40
  промахов), потому что за одним внешним адресом стоит весь магазин: один
  забывчивый продавец не должен запирать остальных.
- **Поток запросов на страницу входа.** Проверка пароля намеренно медленная,
  поэтому поток попыток — дешёвый способ занять процессор. Есть общий потолок:
  120 попыток в минуту на всю систему, и он срабатывает, только если бо́льшая
  часть из них — неудачные (свыше 60). Два условия вместе не случайны: поток
  чужих состоит из неверных паролей, а всплеск у своих — из верных (шесть
  телефонов разом переустановили приложение). По одному лишь количеству система
  заперла бы своих же — то есть сделала бы за нападающего его работу.
  Сверх потолка запросы отбиваются сразу, не тратя процессор, а уже открытые
  смены на телефонах продолжают работать — торговля не останавливается.
- **Ответ на «неверный вход» одинаков** по тексту, коду и времени — независимо
  от того, есть такой логин в системе или нет. Иначе по времени ответа
  перебирают, какие логины существуют, и дальше подбирают прицельно.
- **Подсказка «admin/admin123»** на странице входа показывается только в
  локальной сети. С публичного адреса система о ней молчит, даже если пароль
  и правда стандартный. Владельцу об этом говорит страница «Безопасность»
  после входа.
- **Выгрузки CSV** обезврежены от формул: название изделия, начинающееся
  с «=», не выполнится при открытии файла в Excel.
- **Попытки видны** в журнале действий отдельной строкой на каждую ступень.
- **Cookie входа** недоступна скриптам (HttpOnly), не уходит на чужие сайты
  (SameSite) и по https помечается Secure.
- **Заголовки** запрещают выполнять чужие скрипты (CSP), открывать систему
  в чужом окне и угадывать тип файла; по https включается HSTS.
- **Смена пароля** обрывает вход на всех остальных устройствах.
- **Отключение сотрудника** прекращает его вход немедленно, а не через месяц.
- **Закупочные цены** не уходят продавцам ни в одном ответе системы.
- **Скидка продавца ограничена** (Настройки → Магазин, по умолчанию 15%): отдать
  изделие за бесценок нельзя ни скидкой на позицию, ни скидкой на чек, ни через
  личную скидку клиента — её выше предела назначает только владелец. Сам владелец
  не ограничен, но каждая его скидка сверх предела попадает в журнал действий.
- **Фотографии** отдаются только тем, кто вошёл.

## Что остаётся на вас

- Обновления системы: `bash /home/asher/app/ОБНОВИТЬ-НА-СЕРВЕРЕ.sh` —
  снимает копию, обновляет, перезапускает и проверяет отклик; при неудачном
  старте откатывается на прежнюю версию сам.
- Обновления сервера: `apt upgrade` хотя бы раз в месяц.
- Вход на сам сервер — по ключу, не по паролю.
- Проверять, что копии действительно уезжают наружу.

## Что изменится для вас

**Станет лучше.** Ноутбук можно выключать — система работает всегда. Телефоны
работают из дома, со второй точки, из отпуска. Android предложит установить
приложение в одно нажатие. Заработает сканирование камерой (браузер даёт
камеру только по https). Обновления появляются сразу.

**Появится зависимость.** Пропал интернет в магазине — система недоступна.
Раньше она стояла у вас на столе и работала без интернета. Запасной путь —
раздать интернет с телефона.

**Обмен с 1С придётся перенастроить.** Папка «1С-ОБМЕН» сейчас лежит на вашем
компьютере, и 1С кладёт файлы прямо в неё. После переезда нужно решить, как
файлы будут попадать на сервер.
